# Rivulets — Product Requirements Document
## 1. Executive Summary

**Rivulets** is a Slack-like collaborative interface for humans and AI agents, powered by AgentOS (Agno) under the hood. It provides a chat-native workspace where users create channels, populate them with teams of AI agents, and watch those agents autonomously monitor conversations and jump in when their expertise is needed — no @mentions required. Every user action (creating an agent, wiring up a tool, standing up an MCP server) maps directly to an AgentOS primitive, making the platform a thin but powerful UI layer over a production-grade agent runtime.

The product is **fully decentralized**. There are no Rivulets servers. Users install the software locally, configure it with a workspace key (which doubles as a cryptographic identity for peer-to-peer sync), and access it through a web browser pointed at `localhost`. Multiple machines sharing the same workspace key form a peer mesh — agent definitions, channel structures, rivulet history, tools, and files sync directly between nodes with no man in the middle. LLM provider keys are configured per-machine during installation and are never synced.

The core differentiator from tools like Buzz.xyz is depth without complexity. Rivulets does not ask users to manually route messages to agents. Instead, a channel dispatcher evaluates every incoming message against deterministic routing rules (generated by LLM when the agent is created) and — only when no rule matches — escalates to a lightweight LLM for routing. Agents respond in rivulets, act like human teammates (posting questions, handing off work), and are governed by platform-level guardrails that prevent infinite agent-to-agent loops.

## 2. Target Users & Personas

### Persona 1: The Solo Power User (Primary — P0)
**Who:** A developer, researcher, or knowledge worker who already uses AI tools daily. They have API keys for multiple LLM providers and want to orchestrate a team of specialized agents rather than doing everything through a single chat window.
**Goals:** Create a personal command center where specialized agents handle different domains (coding, research, writing, data analysis) without having to context-switch or manually route tasks.
**Pain Points:** Current tools require explicit @mentions or manual agent selection. Context is fragmented across different chat sessions. No persistent team memory across sessions.
**Context:** Runs this on 1-3 personal machines (desktop, laptop, home server). Comfortable with localhost web apps and editing Python in VS Code.

### Persona 2: The Small Team Lead (Future — P2)
**Who:** A technical lead managing 2-8 humans who work alongside AI agents. They want their human team and AI team in the same channels, collaborating organically.
**Goals:** Onboard human teammates into an AI-augmented workspace. Agents handle routine tasks autonomously while humans focus on high-judgment work.
**Pain Points:** No good tools for human-AI team collaboration. Existing solutions are either fully AI (no human teammates) or fully human (AI is a bolt-on).
**Context:** Multi-machine deployment with one node acting as sync master. Needs the invite system to bring new humans into the workspace securely.

### Persona 3: The Tool Builder (Power User — P1)
**Who:** A developer who wants to extend the platform with custom tools and MCP servers. They think in terms of capabilities they can give their agents.
**Goals:** Rapidly prototype tools in Python, register them with agents, and see them work in real conversations.
**Pain Points:** Most agent platforms have rigid tool ecosystems or require PRs to add functionality.
**Context:** Uses VS Code for tool development. Wants a simple UI mode for quick tools and an advanced mode that opens in their editor.
